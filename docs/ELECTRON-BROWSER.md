# Electron 浏览器复用

桌面浏览器复用仍为显式实验功能。默认发行包保留独立 Chromium；设置 `EDUWORK_EXPERIMENTAL_ELECTRON_BROWSER=1` 后，对应版本的桌面壳与插件才启用复用。Web 和未启用实验的桌面继续使用原有浏览器路径。

## 架构与边界

接入路径为 `DSH 工具／Studio → desktopServices → 已认证 native bridge → 受限 CDP → Electron 独立网页窗口`。DSH 核心、工具权限检查、任务调度和文件系统接口不变。媒体库接受可选的浏览器工厂，不直接依赖 Electron；无注入时仍按原方式解析浏览器。

浏览器服务仅监听随机的本机回环端口，使用随机 Bearer 凭证并拒绝带 Origin 的连接。凭证只经宿主桥接传递，不向网页或客户端 Remote API 暴露。服务通过各受管窗口的 `webContents.debugger` 转发协议，未开启应用级远程调试端口。连接只能列举和操作自己创建的目标、会话及 PDF 数据流，关闭或断开连接会销毁这些窗口。

受管网页禁用 Node 与预加载脚本，启用沙箱；默认拒绝额外权限、下载和弹窗。后台窗口使用离屏渲染，避免隐藏页面截图等待绘制。后台和可见交互浏览器共用独立的持久会话；搜索和文档／视频渲染使用不同的非持久会话，不能读取受管浏览器的登录状态。

工具继续使用 Playwright 完成点击、输入、iframe、Shadow DOM 与整页截图。Electron 缺少的目标创建和 PDF 协议分别映射到 BrowserWindow 与 `printToPDF`。Remotion 适配固定于 4.0.520，升级该依赖时必须重新验证内部接口。

## 本机验证

```powershell
node scripts/probe-electron-browser-reuse.mjs <已装配应用目录> <不存在的测试输出目录>
```

使用独立装配的本地实验候选，不要在下载的已签名发行应用中直接覆盖源码；修改后的发行签名会失效，原生模块可能被 Gatekeeper 拒绝加载。

Windows 传入含 `EduWork-Electron.exe` 的应用目录；macOS 传入 `.app`。macOS 验证器复制独立测试壳、保留 Framework 的相对符号链接并进行本地 ad-hoc 签名，不修改输入应用，也不代表发行包的 Developer ID／公证验收。

验证器从应用目录复用 Electron 二进制，要求对应源码覆盖已经装配到应用目录，并在全新的数据目录启动最小测试壳；不启动正式用户配置，也不开启应用级调试端口。合成测试涵盖认证与 Origin 拒绝、后台／可见切换、Cookie 保留、网页 Node 隔离、可信点击、iframe、Shadow DOM、整页截图、PDF、三路并发搜索、双并发视频渲染、视频与 PCM 音频素材、中文半透明叠层，实际浏览器工具的权限钩子与初始化中停用，以及取消和窗口清理。截图、PDF、视频与结果回执保存在指定目录。该验证器不等于安装验收或真实账号登录验收。

## 当前限制

独立 Chromium 的既有登录资料不会自动导入 Electron 分区，实验模式首次使用需要重新登录；恢复默认后端仍使用原浏览器资料。弹窗登录、下载、上传和特殊权限网站需要独立评估，不能据基础网页测试宣称所有网站兼容。

独立 CLI 不依赖 Electron，它保留原浏览器后端。额外 Chromium 只有在全部调用路径和实际业务验收通过后才能从相应桌面发行配置移除；本实验不会修改公共资源锁。真实音视频项目、机构登录和窗口焦点体验仍需原生人工验收。
